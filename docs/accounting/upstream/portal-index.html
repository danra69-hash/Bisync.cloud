The traps, one per market

Malaysia — SST has no input tax credit. Purchase tax is a cost, not a receivable. And ITA s82(8) requires records kept in Malaysia, which is an infrastructure decision, not a config flag.
Singapore — "Quarterly" is not the calendar quarter. IRAS assigns one of three cycles at registration. Assume calendar and you produce wrong periods for two-thirds of customers.
Australia — N-T and FRE are not the same code. Map wages to "GST-free" and an Australian bookkeeper will reject the product in the demo. Also: BAS truncates cents, never rounds.
Indonesia — the tax invoice number is assigned by DJP after you submit, and the faktur must print 12% with an 11/12 base. A product printing "PPN 11%" is non-compliant.
Thailand — the XML is CII, not UBL (a second serializer), and the VAT tax point for services is payment receipt. Without undue-VAT accounts you overstate the liability every month.
United States — nexus monitoring, not rate lookup, is where bugs create customer liability. Buy the rates. And 1099 thresholds just changed: NEC $2,000, 1099-K back to $20,000 + 200.

Sequence

Malaysia first because it exercises every hard part of the framework. Singapore second because it is the architectural opposite — that pairing is what proves the abstraction rather than merely accommodating one regime. Do not start markets 4–6 until 1–3 are live with paying customers.

2Malaysia s82A legal advice — what satisfies "records kept in Malaysia" for cloud-hosted books. Gating for the whole market.
3MyInvois intermediary registration — customers authorise your platform in the LHDN portal; onboarding UX depends on it.
4SOC 2 evidence collection — retrofitting a year of evidence is impossible, and US buyers ask before signing.
5A qualified accountant per market — one per pack, before that pack starts. Their sign-off is recorded against the pack version.

Eleven capabilities, zero conditionals

A pack is a versioned, effective-dated bundle of data and adapters for one jurisdiction, loaded per legal entity — a tenant with a Malaysian Sdn Bhd and a Singaporean Pte Ltd runs two packs at once without interference.

CapabilityQuestion it answers
chart_of_accountsIs a statutory chart prescribed, and how does the internal chart map to it?
tax_determinationWhich tax code, rate and base apply to this transaction?
tax_pointWhen does the liability arise — invoice, payment, delivery?
rounding_policyLine, tax-category or invoice level? Which mode? Which unit?
numbering_rulesGapless? Chronological? Externally assigned? Format? Reset cadence?
document_contentWhich fields are mandatory, in which language?
transmissionClearance, Peppol, e-mail, or nothing?
withholdingWhich payments withhold, at what rate, with what certificate?
returnsWhich periodic returns exist, and how do they aggregate?
statutory_exportsAnnual filing formats — XBRL taxonomies, return-line maps
archive_policyRetention years, residency, which artefact must be kept

Returns are YAML, not code

Every return in all six markets is an aggregation over tagged transactions. Every tax code carries its return-box tags, so adding a country's return is a data file rather than a sprint.

boxes: - { id: "1", label: "Standard-rated supplies", source: sum(net) where tax_code.group == "SR" } - { id: "6", label: "Output tax due", source: balance("GST Output Tax") } - { id: "8", label: "Net GST", source: box(6) - box(7), posts_to: "GST Control" }

Five gates — a pack is not done until all pass

GateChecks
G1 Golden documentsFixtures render byte-comparable to expected output, sourced from the authority's own samples where they exist
G2 SchemaOutput validates against the official XSD/schematron — vendored and versioned, never fetched at runtime
G3 Sandbox round-tripSubmit to the authority's sandbox; assert the expected acceptance or error code. Nightly, not per-PR
G4 Return reconciliationEvery return box equals an independently computed value from journal_line
G5 Determination coverageEvery tax code exercised, every rule reachable. Uncovered rules fail the build

Plus one cross-cutting gate: no pack may import from ledger.* internals. Enforced with an import-linter contract in CI.

Open items that gate estimates

Every country document ends with a §9 list of what could not be verified against a primary source, or where sources conflicted. These are not padding — four of them carry ±2 weeks of estimate risk each.

1Malaysia — Service Tax Regulations 2018 First Schedule: the Group A–L list and per-group thresholds. Blocks the tax-code taxonomy.
2Indonesia — PMK 141/PMK.03/2015 annex: the enumerated PPh 23 service list. Blocks withholding determination.
3Indonesia — e-Faktur Desktop / host-to-host status in 2026 after the Coretax rollout. The single most consequential unknown in the set.
4Thailand — DBD XBRL taxonomy version and submission mechanism (Excel template vs raw XBRL).

This set was fact-checked against primary sources after drafting, and ten material errors were corrected — a Malaysian service-tax group that does not exist, two thresholds that had doubled, a Singaporean withholding rate that would have under-withheld on every non-resident director fee, and an Indonesian MSME regime rewritten by PP 20/2026 in April. Four open items were closed in the same pass.

Compliance facts decay. Re-verify each pack's rates and dates at every version bump, and record the qualified accountant's sign-off against that version — it is what you show an auditor and what protects you when a rule changes.
